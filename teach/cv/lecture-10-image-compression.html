1.
Fundamentals

Why Compress?

Goal: Represent an image with fewer bits by removing redundancy — saving storage and transmission bandwidth.

$$\text{Compression ratio} \; C = \frac{b}{b'}$$

$b$ = original bits, $b'$ = compressed bits

A raw 24-bit HD image is ~6 MB — compression makes it practical to store and stream.

Three Kinds of Redundancy

Coding redundancy

Using more bits than needed — fixed-length codes waste space when symbols have unequal probabilities.

Spatial (& temporal) redundancy

Neighboring pixels are highly correlated — the same information repeats across space (and video frames).

Psychovisual redundancy

Information the human eye cannot perceive — can be discarded with little visible loss.

Lossless vs. Lossy

Lossless Lossy
Exact reconstruction Approximate reconstruction
Removes coding & spatial redundancy Also removes psychovisual redundancy
Modest ratios (PNG, GIF) High ratios (JPEG)

2.
Lossless Compression

Entropy & Coding

Entropy is the theoretical lower bound on average bits per symbol:

$$H = -\sum_{k} p_k \log_2 p_k \quad \text{(bits/symbol)}$$

  • Assign short codes to frequent symbols, long codes to rare ones
  • These variable-length codes are called entropy codes

Huffman Coding

Builds an optimal prefix code by repeatedly merging the two least-probable symbols into a binary tree.

  • No code is a prefix of another → uniquely decodable
  • Optimal among symbol-by-symbol codes
  • Used inside JPEG, PNG, ZIP

Run-Length & Predictive Coding

Run-Length Encoding (RLE)

Replace runs of identical pixels with (value, count) pairs. Great for large uniform regions.

AAAAABBB → (A,5)(B,3)

Predictive (DPCM)

Store the difference between a pixel and a prediction from its neighbors — small differences compress well.

Key Idea: These attack spatial redundancy; entropy coding then attacks coding redundancy.

3.
Lossy & Transform Coding

Transform Coding

  • Transform the image into a domain where energy is concentrated in a few coefficients
  • Most coefficients become near-zero and can be discarded or coarsely quantized
  • The Discrete Cosine Transform (DCT) is the workhorse — a real-valued relative of the Fourier transform

Block-Based Coding

The image is split into small blocks (typically 8×8), each transformed and quantized independently.

  • Keeps computation local and fast
  • Quantization discards perceptually unimportant high frequencies
  • Too much compression → visible blocking artifacts

4.
The JPEG Standard

The JPEG Pipeline

1

Color transform — RGB → YCbCr, subsample chroma (eye is less sensitive to color)

2

Block DCT — split into 8×8 blocks and transform each

3

Quantize — divide by a quantization table (the lossy step)

4

Entropy code — zig-zag scan, run-length + Huffman coding

Quality vs. Compression

A quality factor scales the quantization table:

  • High quality → gentle quantization, large files
  • Low quality → aggressive quantization, small files, artifacts
  • Quality is measured with PSNR / SSIM (Lecture 9)

Summary

  • Compression removes coding, spatial, and psychovisual redundancy.
  • Lossless coding (Huffman, RLE, DPCM) reconstructs exactly; lossy coding trades quality for size.
  • Transform coding with the DCT concentrates energy so most coefficients can be dropped.
  • JPEG: color transform → 8×8 DCT → quantize → entropy code.
  • A quality factor controls the trade-off between file size and fidelity.
